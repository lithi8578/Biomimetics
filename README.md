# 工作包 A：情境與資料（0-2 測試情境腳本、1-1 合成情境產生器）

這是一支假的眼動儀。它把「什麼時間、使用者在看多遠的東西」的腳本，轉成眼動儀會輸出的左右眼視線角（含雜訊、眨眼、遺失），同時另存一份標準答案（真值）給指標計算用。

## 怎麼跑

需要 Python 3.10 以上、numpy、matplotlib。以下指令都在「Biomimetics」資料夾執行。

```bash
python -m unittest sim.tests.test_workpackage_a -v
```

```bash
python -m sim.generator --scenario all --preset mid --seed 0 --out-dir out
```

```bash
python -m sim.make_examples
```

第一行跑驗收測試；第二行產生資料（可加 `--sigma 0.5`、`--blink-rate 15`、`--dropout 0.05`、`--fs 120`）；第三行重新產生 `examples/` 裡的範例與圖。

在自己的程式裡用：

```python
from sim.scenarios import get_scenario
from sim.generator import generate, make_config

measured, truth = generate(get_scenario("near_far"), make_config("mid", seed=0))
# measured["theta_L_deg"], measured["valid_L"], ...；truth["demand_true_D"], ...
```

## 4 支必做腳本（0-2）

焦度區段參考值：FAR ≈ 0.5 D（2 m）、MID ≈ 1.43 D（70 cm）、NEAR ≈ 2.86 D（35 cm）。

| 腳本 | 長度 | 內容 | 要考的是 |
| --- | --- | --- | --- |
| ① `near_far` 近遠切換 | 30 s | 2 m → 35 cm → 70 cm → 2 m（各 5 s）→ 70 cm → 35 cm（各 3 s）→ 2 m | 該切的時候切得夠不夠快、夠不夠準 |
| ② `same_depth_scan` 同深度左右掃視 | 30 s | 0–16 s 在 70 cm 螢幕上 ±15° 四處看（每 0.25–0.6 s 跳一次）；16 s 起看 35 cm 的書，逐行閱讀（每 0.2–0.3 s 右移 2°，行尾跳回行首） | 距離沒變時會不會亂切。全程只有 16 s 一次合理切換 |
| ③ `blink_loss` 眨眼與資料遺失 | 34 s | 70 cm → 2 m → 35 cm → 70 cm（每 8 s 換一次）。途中：100／150／200／300 ms 眨眼、500 ms 長眨眼、雙眼遺失 1.2 s、換目標的同時眨眼、左眼或右眼單獨遺失 0.4 s、27–30 s 追蹤全失效 3 秒 | 沒資料時會不會保持原狀；逾時後會不會退回預設焦度 |
| ④ `threshold_jitter` 門檻附近抖動 | 30 s | 2 m → 5–25 s 目標在 0.8–1.2 D（約 0.83–1.25 m）之間緩慢晃動 → 35 cm | 遲滯有沒有擋住來回跳動。中段 FAR 或 MID 都算對，但段內最多切換 1 次 |

③ 最後的「追蹤全失效 3 秒」是為了 1-5 的 HOLD 逾時與 1-9 的故障案例，順便放進來。

## 輸出欄位

**量測檔**（`<腳本>_<預設>_s<種子>.csv`）：控制程式唯一能讀的檔案。

| 欄位 | 單位 | 說明 |
| --- | --- | --- |
| `t_ms` | ms | 時間戳，預設 100 Hz（每 10 ms 一筆） |
| `theta_L_deg`、`theta_R_deg` | 度 | 左右眼水平視線角，向右為正。**無效時是空白（讀進來是 NaN）** |
| `valid_L`、`valid_R` | 0／1 | 這一筆這隻眼睛有沒有量到 |
| `confidence` | 0–1 | 兩眼可信度取較小者 |
| `dist_est_m`、`demand_D`、`state`、`cmd_D`、`lens_D` | | 留空，由下游模組填 |

**真值檔**（`..._truth.csv`）：只給指標計算（1-7）和畫圖用，控制程式不可以讀。

| 欄位 | 說明 |
| --- | --- |
| `target_dist_m`、`demand_true_D` | 使用者正在看的目標距離，與真實屈光需求 = 1 / 距離 |
| `version_true_deg` | 目標方向角 |
| `theta_L_true_deg`、`theta_R_true_deg` | 眼睛真正的視線角（含掃視過程，不含量測雜訊） |
| `eye_event` | `fix` 注視、`sac` 掃視、`verg` 輻輳移動、`blink` 眨眼、`loss` 追蹤遺失。1-4 可以拿來算「掃視被誤判為穩定」的比例 |
| `zone_intent` | 腳本預期的區段：`FAR`／`MID`／`NEAR`；`FAR/MID` 表示兩者都可以 |
| `section_id` | `zone_intent` 改變時才加 1。**同一個 section 內的狀態切換，第一次之後都算不必要切換** |
| `target_id` | 每換一次注視目標加 1（包含同深度掃視） |

## 雜訊預設值

| 預設 | 每眼雜訊 σ | 掃視中的暫時發散 | 用途 |
| --- | --- | --- | --- |
| `ideal` | 0 | 無 | 除錯：輸出應該和真值完全一致 |
| `low` | 0.5° | 有 | 1-9 雜訊掃描 |
| `mid` | 1.0° | 有 | 預設、範例資料 |
| `high` | 2.0° | 有 | 1-9 雜訊掃描 |

其他參數都在 `generator.NoiseConfig`：取樣率、左右眼固定偏差（模擬校正誤差）、隨機眨眼頻率、隨機遺失比例、輻輳移動時間、瞳距。預設的隨機眨眼與隨機遺失都是 0，讓腳本裡安排的事件是唯一的干擾；1-9 要掃「資料遺失率」時再打開。

## 注意事項

1. **一定要先看有效旗標。** 無效樣本的視線角是 NaN，直接拿去算會讓整條鏈變 NaN。這是故意的，免得錯誤被藏起來。
2. **反算請用屈光度，不要用公尺。** 看 2 m 時，雜訊會讓輻輳角變成 0 或負的，距離就變成無限大或沒有定義。實測比例（每眼 σ = 0.5／1／2°，600 秒）：0.5%／9.6%／25.7% 的樣本是這樣。`geometry.demand_from_angles` 對這種情況仍回傳有限的數字（可能是負的），由 1-2 決定怎麼截斷。
3. **單筆樣本的屈光需求標準差：0.19／0.39／0.77 D（σ = 0.5／1／2°）。** 和誤差傳遞公式 δq ≈ δθ√2 / b 的預測一致，1-3 可以直接拿來對照。換句話說，σ = 1° 時不做時間窗平均，單筆就超過 ±0.25 D 的門檻。
4. **同深度掃視時，真實輻輳角也會短暫變小。** 水平掃視時兩眼不完全同步，掃視中會出現「掃視幅度 × 0.1」的暫時發散（例如 20° 掃視約 2°）。這是眼睛本身的行為，不是量測雜訊，所以就算是完美的眼動儀，策略 B 也可能在腳本 ② 誤切換。
5. **可信度不會洩漏掃視。** 可信度只在眨眼前後 50 ms（眼皮半閉）降到 0.3–0.6，那段雜訊也放大 3 倍；掃視期間可信度照常。1-4 要從視線角的變化速度自己判斷掃視。
6. **目標偏離正前方時，報告的公式 z = b / [2 tan(θ/2)] 會有誤差**（偏 15° 時約 3.4%）。`geometry.distance_from_angles` 用兩條視線交點計算，任何方向都精確。

## 待確認

| 項目 | 目前設定 | 為什麼這樣設、可以怎麼改 |
| --- | --- | --- |
| 取樣率 | 100 Hz | 常見眼動儀在 60–200 Hz；`--fs` 可改 |
| 腳本 ④ 的中心 | 1.0 D | 位於 FAR 與 MID 之間。工作包 D 訂好門檻後，用 `threshold_jitter(center_D=...)` 對齊 |
| 掃視中的暫時發散 | 掃視幅度 × 0.1 | 依據 Collewijn 等人 1988 年對雙眼水平掃視的觀察（掃視中會短暫發散），但 0.1 這個倍數是我取的量級，**請有人查原文確認**；`saccade_vergence_k` 可改，設 0 即關閉 |
| 輻輳移動時間 | 和掃視同時完成（20–80 ms） | 依 1-1 的規格。真實眼睛純近遠切換的輻輳移動常要數百毫秒，會讓延遲指標變差；`vergence_ms` 可改，1-9 可以把它當敏感度參數 |
| 只模擬水平方向 | 低頭看手機也當成正前方 | 垂直視線角不影響輻輳距離，本期不需要 |
| 可信度模型 | 正常約 0.95，眨眼前後 0.3–0.6，無效 0 | 只是合理的假設，不是某款眼動儀的規格 |
